# 技术路线与详细设计 v0.1（snail-agent · 最强蜗牛攻略智能体）

> 日期：2026-09-08
> 状态：设计阶段（SDLC ②），待确认后进入开发
> 原则：**阶段渐进、每阶段留口子、阶段成果可见**——不一步到位，一个阶段能在聊天页"看到东西"再进下一阶段。

## 一、分阶段演进总览（P0 → P3）

| 阶段 | 主题 | 可见成果（演示点） | 里程碑对应 |
|---|---|---|---|
| P0 | 地基 | `/api/health` 绿、SQLite 建库骨架、离线 pytest 绿 | 服务骨架 |
| P1 | **知识库 + RAG 问答** ⭐ | 建库后，聊天页问"新手前期刷哪个图"→ 带引用来源的回答 + 来源列表 | 建库+RAG |
| P2 | **多模态/文档解析（对话+建库）** | 发图片/文档/网页链接/文本，智能体看懂并回答；图片 OCR 入库 | 解析引擎 |
| P3 | **管理后台 + 增强** | `/admin` 知识库管理/系统运维/模型管理；分类入口、结构化速查 | 管理后台 |

> 演进顺序：先能针对已有攻略全文问答（P1），再让智能体"看"各种外部输入（P2），最后配套管理后台做内容与配置运维（P3）。这与需求确认的"两者都要"（对话解析+建库解析）与"管理后台需要"一致。

## 二、技术架构总览

```
用户输入                                  snail-agent 服务（FastAPI, port 19240）
┌──────────────┐   SSE / fetch    ┌───────────────────────────────────────────────┐
│  聊天页(web)  │ ───────────────▶ │  server/api/                                  │
│  管理后台     │◀──────────────── │   main.py        routes_chat.py              │
└──────────────┘                  │       routes_upload.py      routes_admin.py │
                                  ├───────────────────────────────────────────────┤
                                  │  server/orchestrator/  意图路由（咨询/解析）      │
                                  │  server/rag/                                   │
                                  │   parser.py  解析层(网页/PDF/Word/Excel/PPT/   │
                                  │   ──── 图片/文本 + 图片双通道OCR)               │
                                  │   chunker.py  切块       kb.py  检索(混检)      │
                                  ├───────────────────────────────────────────────┤
                                  │  server/core/                                  │
                                  │   models.py 统一模型 │ config.py │ llm.py      │
                                  │   vision.py 多模态(qwen-vl)                    │
                                  │  server/admin/store/  管理存储(repository)      │
                                  ├───────────────────────────────────────────────┤
                                  │  SQLite 知识库(data/kb.sqlite3)                │
                                  │  SQLite 管理库(data/admin.db)                  │
                                  └───────────────────────────────────────────────┘
        外部：DashScope（qwen-plus / qwen-vl / text-embedding-v3）· PaddleOCR(可选)
```

### 分层职责
- **api 层**：HTTP 入口，SSE 流式；路由按功能拆（chat / upload / admin）
- **orchestrator 层**：意图路由——纯咨询走 RAG；带附件/链接走"解析 → 并入上下文 → 回答"
- **rag 层**：解析（parser）+ 切块（chunker）+ 检索（kb），纯逻辑可离线测试
- **core 层**：统一模型、配置、LLM/embedding 客户端、多模态客户端（跨模块唯一出处）
- **admin 层**：管理存储 repository，与 SQLite 解耦（切库只换实现）

## 三、各阶段详情

### P0 地基

- **范围**：FastAPI 服务骨架、`.env` 配置（pydantic-settings）、`server/core/models.py` 统一模型、健康检查 `/api/health`、建库脚本骨架 `scripts/build_kb.py`、离线冒烟测试 `tests/test_health.py`、记忆机制
- **可见成果**：`GET /api/health` 显示 service/llm 状态；`pytest tests/` 绿
- **预留口子**
  - `server/core/models.py`：统一数据模型唯一出处（P1 填 Chunk/Document，P2 填解析结果模型）
  - `SqliteStore` 抽象（kb 底层），切库只换实现
  - SSE 事件基础：`sources → delta → error`，P2 扩 `parsed` 事件
  - 意图路由骨架：P1 纯咨询；P2 扩解析
- **验收**：health service=up；离线测试通过；新机器按 env-setup 可起
- **新增依赖**：fastapi / uvicorn / pydantic-settings / openai / numpy / rank-bm25 / pymupdf / pdfplumber / python-docx / openpyxl / python-pptx / pandas / beautifulsoup4 / httpx

### P1 知识库 + RAG 问答 ⭐ 第一个可见成果

- **范围**：
  - `scripts/build_kb.py`：解析 `knowledge/raw/` 下 PDF/Word/HTML/文本 → 切块 → text-embedding-v3 向量化 → 入 SQLite（向量 BLOB + FTS5 关键词表）
  - `POST /api/chat`：检索（向量近似 + BM25 混检）→ 拼 prompt → SSE 流式回答；回答强制引用来源（文件/章节/原片段）
  - 聊天页 `index.html`：SSE 消费 + `sources` 渲染 + 分类入口占位
- **可见成果**：放入数份攻略材料建库后，聊天页提问"新手前期刷哪个图收益最高" → 带引用来源的回答 + 来源文件列表
- **预留口子**
  - RAG 引擎独立模块（parser/chunker/kb 解耦），P2 直接复用 parser 扩展格式
  - 检索上下文结构预留 `tags`（多标签字段，OR 过滤），P3 分类入口使用
  - 密令/兑换码结构化表预留（P3 可落 structured 表）
- **验收**（需求验收 1、2、3、5）：建库可统计条数；知识库内问题带正确来源；库外问题明确"未找到"不编造
- **测试**：chunker 纯函数单测（离线）；parser 对样例文件；`/api/chat` 用 mock 检索（不依赖真实 Key）
- **前置**：DASHSCOPE_API_KEY 配置

### P2 多模态 / 文档解析（对话 + 建库）⭐

- **范围**：
  - **解析层 `server/rag/parser.py`**：按扩展名分发——网页（httpx 抓取 + BeautifulSoup 提取正文）、PDF（pymupdf/pdfplumber）、Word（python-docx）、Excel（openpyxl/pandas 多 sheet）、PPT（python-pptx）、纯文本（直接）、图片（双通道）
  - **图片双通道**：`server/core/vision.py`——多模态 `qwen-vl`（看懂+提取语义，走 OpenAI 兼容 image_url）+ 离线 `PaddleOCR`（批量文字提取，可选依赖）；通道策略：对话单张/少量用多模，批量建库优先 OCR
  - **场景 A（对话直接解析）**：聊天接口支持上传图片/文档、粘贴网页链接/文本；解析结果并入上下文后回答；SSE 新增 `parsed` 事件回显解析出的文本摘录
  - **场景 B（建库批量解析）**：`scripts/build_kb.py` 支持上述全部格式图片经 OCR；网页可批量抓取列表
- **可见成果**：聊天页发一张攻略截图 → 智能体看懂并回答"这个装备怎么培养"；粘贴一个网页链接 → 提取正文并回答；图片批量入库可被检索
- **预留口子**
  - vision 抽象为 `ImageReader` 接口（多模/OCR 两个实现），可替换/新增第三通道
  - 解析结果统一 `ParsedContent(text, meta, source_type)`，RAG 与对话上下文共用
  - 网页批量抓取做成可插拔的 fetcher（可接 sitemap/列表页）
- **验收**（需求验收 8、9）：上传含文字图片能解析并回答；粘贴网页链接能提取正文；图片 OCR 能入库并检索命中
- **测试**：parser 各格式纯函数单测（离线，构造样例文件）；图片通道用 fixture/mock 隔离（不依赖真实 Key/PaddleOCR）；`/api/chat` 附件流程 mock
- **前置**：P1 完成；qwen-vl 模型可用；PaddleOCR（可选装）

### P3 管理后台 + 增强

- **范围**：
  - **管理后台 `/admin`**（原生 HTML，`web/admin/`）：
    1. 知识库管理：上传（PDF/Word/Excel/PPT/HTML/图片）、条目列表/删除/统计、触发重建索引、标签维护、检索测试
    2. 密令管理：密令列表/新增/批量导入/停用/设有效期（2.6 / D13）
    3. 系统运维：service/llm 状态卡片（复用 `/api/health`）、解析/OCR 任务状态、日志查看
    4. 模型管理：LLM/Embedding/多模态配置（base_url/model/Key 状态检测）、测试对话；持久化 SQLite，不进 git
  - **增强**：
    - 聊天页**多标签过滤**（新手/探索/周活动/密令/进阶，可多选）——复用检索 `tags` 过滤
    - 管理后台标签维护（增删标签、给条目打多个标签）
    - 密令结构化查询工具 `query_codes`（ToolRegistry，MCP 规范）——精确返回 码+奖励+是否生效
- **可见成果**：打开 `/admin` 管理知识库/密令/模型配置；聊天页按多标签过滤问题、问密令精确返回
- **预留口子**：管理 API 走 repository 模式与存储解耦（切库只换实现）；ToolRegistry 承接结构化查询工具，三期可拆 MCP server；密令回答卡片提供「复制全部」（客户端取生效密令以 `\n` 拼一行一条、`navigator.clipboard` 写入）
- **验收**（需求验收 4、6、11）：health 状态如实；知识库页可列出条目并触发重建；模型配置可查看/测试；密令问题精确返回状态
- **测试**：管理 API 冒烟（离线；SQLite 用 tmp_path 隔离）；多标签过滤检索单测；密令查询工具单测

## 四、关键模块详细设计

### 4.1 统一数据模型 `server/core/models.py`（D7）
> 跨模块数据唯一出处，禁止各模块重复定义。

```python
# -*- coding: utf-8 -*-
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class Document:          # 建库/管理后台：一份原始攻略材料
    id: Optional[int]
    title: str           # 标题/来源文件名
    source_type: str     # pdf/word/excel/ppt/html/txt/image
    raw_path: str        # 原始路径（gitignore 区）
    created_at: str

@dataclass
class Chunk:             # 切块后的检索单元
    id: Optional[int]
    doc_id: int
    title: str           # 所属文档
    section: str         # 章节/标题
    page: Optional[int]  # 页码（若有）
    text: str            # 块文本
    vector: list         # embedding（96/1024 维）
    tags: list = []      # 分类标签（多标签，P3 过滤），如 ["新手入门","探索地图"]

@dataclass
class ParsedContent:     # P2：解析层统一输出
    text: str
    source_type: str
    meta: dict = field(default_factory=dict)   # 标题/章节/页码/OCR通道等

@dataclass
class Code:              # 密令（兑换码）结构化条目（P3，D13）
    id: Optional[int]
    text: str            # 密令/兑换码文本
    reward: str          # 兑换奖励
    status: str          # 生效/停用/已过期
    valid_until: str = ""       # 有效期（可空）
    batch: str = ""             # 批次/来源
    remark: str = ""
```

> 标签为**多标签**（D12）：一条内容可挂多个标签，检索时多个标签任一命中即可（OR 语义），管理后台可维护。

### 4.2 检索：SQLite 向量近似 + FTS5/BM25 混检（D4）

- 表 `chunks`：`id, doc_id, title, section, page, text, vector(BLOB), tags(JSON)`；P3 起按 tags 过滤
- 表 `chunks_fts`（FTS5）：对 `text / section / title` 建虚拟表做关键词检索
- 流程（`POST /api/chat` 与 `scripts/build_kb.py` 检索共用）：
  1. 问题 → text-embedding-v3 向量化
  2. 向量路径：numpy 余弦相似度近似 Top-K（BLOB → 向量）
  3. 关键词路径：FTS5 + BM25 得分 Top-K
  4. **混检融合**：两路结果按 `score = α·sim + (1-α)·bm25`（默认 α=0.6，P3 可配）加权排序取最终 Top-K；命中同一块则合并取高分
  5. **多标签过滤**：检索可带 `tags` 参数（P3），任一标签命中即返回（OR 语义），同时保留标签供前端分类展示

## 五、技术选型全景与理由

> 原则（AGENTS.md）：新增依赖必须写进 requirements*.txt，并在技术栈表注明选型理由；禁止无理由的重型依赖。

| 层 | 子层 | 技术 | 选型理由 | 备选/升级 |
|---|---|---|---|---|
| 语言 | 运行时 | Python 3.12 | 主流 AI 生态（解析/向量/多模）最成熟 | — |
| 服务 | Web 框架 | FastAPI | 异步 + SSE 流式开箱即用 | Flask（需拼SSE） |
| 服务 | ASGI | uvicorn | 轻量、`--reload` 开发友好 | gunicorn（生产） |
| 服务 | 配置 | pydantic-settings | `.env` 类型化，零写死密钥 | os.environ |
| 大模型 | LLM | 通义千问 DashScope（qwen-plus） | OpenAI 兼容，便宜可验证；切私有化只改 base_url/model（D2） | 内网 vLLM |
| 大模型 | 多模态 | qwen-vl（DashScope） | 同一接口 image_url，看懂图片提取语义，无本地重依赖（D9） | 其它多模 API |

| 测试 | 单元/接口 | pytest + httpx | TestClient 原生；离线优先 mock 隔离（D7） | unittest |

## 七、贯穿性工程约束

- **口子优先**：每阶段结束时，下一阶段要接的数据结构与接口已留好，禁止临期改接口
- **测试随行**：每阶段配离线 pytest（纯函数优先、外部依赖 mock），未过测试不视为完成（D7）
- **文档同步**：每阶段完成更新设计文档相关章节 + `progress.md`（D9）
- **可演示**：每阶段结束都能在聊天页演示，不搞黑箱
- **保密红线**：只用公开/脱敏攻略数据；攻略原文只留建库脚本与脱敏示例，知识原文 gitignore（AGENTS.md）
- **依赖纪律**：新增依赖写进 requirements*.txt 并在此表注明理由；重型依赖（PaddleOCR）单独文件可选装（D9）
